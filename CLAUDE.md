## Architecture

The game is named **Tank Royale**. It is a SvelteKit + Three.js tanks game using [Threlte](https://threlte.xyz/) (Three.js bindings for Svelte 5).

**Route flow:**
- `src/routes/+page.svelte` — Mode-select landing page: player name input (persisted to `localStorage`), "Single Player" → `/single`, "Multiplayer" → `/multi` (disabled until a name is entered)
- `src/routes/single/+page.svelte` — Single-player setup: AI opponent count 1–5 (radio chips), Mute checkbox, Start Game; calls `unlockAudio()` in `startGame()`; navigates to `/game?opponents=N&muted=1`
- `src/routes/multi/+page.svelte` — Multiplayer lobby: connects WebSocket via `mp` store, lists open rooms (`RoomSummary[]` from `lobby_update`), create room button, join request flow; navigates to `/multi/[roomId]` on `join_accepted`
- `src/routes/multi/[roomId]/+page.svelte` — Room waiting page: player list with per-player color picker (6 swatches, taken colors dimmed), AI opponent stepper (0–4, any member may change), incoming join-request panel with Accept buttons, countdown progress bar + Start/Cancel/Join-Countdown actions; handles direct-URL navigation by sending `request_join` on connect
- `src/routes/game/+page.svelte` — Parses `opponents` (capped at 5, min 0) and `muted` query params; wraps `<Scene>` in `<Canvas shadows>`; calls `buildGameSetup()` synchronously at module-init (before any child mounts) to produce `gameSeed`, `tankNames`, `tankColors`, and `relayToLocal: Map<relayTankIndex, localBarIndex>` from `mp.gameStart` or sessionStorage fallback; handles `mp.latestPlayerLeft` via `$effect` to mark disconnected tank as destroyed (using `relayToLocal` to convert relay index to local bar index) and show a 5 s notification banner; `onDestroy` sends `leave_room`, clears `mp.room/gameStart`, and removes sessionStorage keys; renders HTML health bars with vertical names and game overlay
- `src/routes/game/Scene.svelte` — Accepts `opponentCount`, optional `seed` (multiplayer game seed), optional `tankNames[]` and `tankColors[]` props; `TANK_COUNT = opponentCount + 1`; uses `seed ?? random` for `gameSeed`/`rand`; in `initGame()` populates `tankHealthData[i].name` from `tankNames[i]` (defaulting `'You'`/`'AI N'`) and `tankHealthData[i].color` from `tankColors[i]` (falling back to `TANK_COLORS[i]`); same fallback applied to `tankColor` prop on each `<Tank>`
- `src/lib/Tank.svelte` — Self-contained tank: physics, keyboard/mouse input, turret/barrel control, chase camera, directional light — all controlled by `controlled` and `chaseCamera` boolean props; `onfire` prop called with `(position, velocity)` when a shell is fired
- `src/lib/Shell.svelte` — Self-contained shell: clones initial position/velocity, owns its own `useTask` physics loop, handles water splash and terrain impact
- `src/lib/Explosion.svelte` — Fireball + flying rocks with ballistic physics; rocks trigger `<Splash>` on water crossings; delays removal until all rocks landed and all splashes complete
- `src/lib/Splash.svelte` — Reusable water splash: 3 staggered expanding `RingGeometry` rings fading over 2 s; calls `onremove` when all rings finish; used by both Shell and Explosion
- `src/lib/Flames.svelte` — Imperative fire effect component: 6 `ConeGeometry` flame meshes + `PointLight`, all in a `THREE.Group` added directly to the scene. Props: `x`, `y`, `z` (world base position), `baseHeight` (Y offset above base where flames start — `0.3` for tanks), `burning` (controls visibility), `scale` (multiplies all geometry sizes and spread positions; default 1.0), `flameCount` (active flames 1–6; default 6), `burnDuration` (seconds until flames fully die out via cubic falloff; 0 = no fade, default). Uses `MeshStandardMaterial` with emissive for glow effect. Manages its own `elapsed` timer; resets when `burning` goes false. Shader warmup via `renderer.compile` on first tick.
- **HTML health bars (`+page.svelte`):** Tank health is rendered as HTML overlays, not in-world. `Scene.svelte` exposes a `tankHealthData: {health, destroyed, color, name}[]` `$bindable` prop; `+page.svelte` binds to it and renders two HUD regions: player bar (bottom-right, 22×50 vh vertical, fills bottom-to-top) and opponent bars (bottom-left, up to 5 × 14×90 px side-by-side). Each bar has a vertical bottom-to-top name label (`writing-mode: vertical-lr; transform: rotate(180deg)`). Player bar label is 10 px, opponent labels 7 px. Names come from `tankNames[]` prop passed to Scene: player gets localStorage name, AIs get `AI 1 / AI 2`, multiplayer humans get their room display name. Destroyed tanks fade to 30% opacity. When a multiplayer player disconnects (`mp.latestPlayerLeft`), their `tankHealthData` entry is set to `{health:0, destroyed:true}` immediately, triggering the existing `gameOver` derived. A 5 s notification banner (`player-left-notif`) appears above the charge bar.

**Prettier config:** tabs, single quotes, no trailing commas, 100-char line width. VS Code is configured (`.vscode/settings.json`) to run Prettier on save. Re-read any file after editing it before making further edits, in case Prettier has reflowed it.

**TypeScript:** strict mode enabled; uses bundler module resolution.

## Key patterns

**Svelte 5 reactivity with Three.js objects:** Mutating `.x/.y/.z` on a `$state` Vector3 does NOT trigger re-renders. Always reassign: `tankPosition = new THREE.Vector3(x, y, z)`.

**Threlte per-frame loop:** `useTask((delta) => { ... })` — `delta` is seconds since last frame.

**Terrain generation** (`Scene.svelte`): `PlaneGeometry` in XY plane, heights stored in Z, then `rotateX(-Math.PI/2)` maps Z → world Y. Heights use bilinear interpolation via `getTerrainHeight(wx, wz)`. Vertex colors set via `BufferAttribute` on `'color'` attribute + `vertexColors` on `MeshStandardMaterial`. `getTerrainHeight` is shared to child components via `setContext('getTerrainHeight', fn)`; returns `0` for out-of-bounds coordinates. `isInBounds(wx, wz)` (same grid math, exposed via `setContext('isInBounds', fn)`) returns false for the same OOB cases.

**Tank rotation order — critical:** Use nested groups to avoid Euler XYZ interaction between heading and pitch/roll:
```svelte
<T.Group position={[x, y, z]} rotation.y={tankHeading}>
  <T.Group rotation.x={tankPitch} rotation.z={tankRoll}>
    <!-- tank meshes -->
  </T.Group>
</T.Group>
```
Putting all three angles on the same object with XYZ order causes pitch/roll to be heading-dependent (world-space axes, not tank-local axes).

**Tank pitch/roll from terrain normal:**
```js
const dhdx = (getTerrainHeight(x+ε, z) - getTerrainHeight(x-ε, z)) / (2ε);
const dhdz = (getTerrainHeight(x, z+ε) - getTerrainHeight(x, z-ε)) / (2ε);
const slopeForward = dhdx*(-sinH) + dhdz*(-cosH);  // project onto tank forward
const slopeRight   = dhdx*cosH   + dhdz*(-sinH);   // project onto tank right
targetPitch = +Math.atan(slopeForward);  // positive = nose up
targetRoll  = +Math.atan(slopeRight);   // positive = right side up
```

**Tank Y positioning — track corners:** Tank Y is set to `max(requiredY)` over the 4 track-belt corners `(±TRACK_W, 0, ±TRACK_L)` in local space, transformed to world XZ. Each corner's required Y accounts for the current tilt:
```js
requiredY = getTerrainHeight(cornerWx, cornerWz) + lz*sin(pitch) - lx*sin(roll)
```

**Gravity / grounded physics:** `velocityY` accumulates gravity each frame. When `newY <= groundY`, the tank is clamped to `groundY` and `velocityY` reset to 0. Keyboard input and slope limits are gated on `velocityY === 0` (grounded last frame).

**Water drag:** Detected when `getTerrainHeight(x, z) < 0` (terrain below sea level). Each physics object applies `vel *= pow(WATER_DRAG, delta)` per frame while `pos.y <= 0` in a water area, before gravity is added. Drag constants: shell `0.8`, explosion rocks `0.6`, tank `0.85` (applied via `speed *= pow(WATER_TANK_DRAG, delta)` inside the `if (speed !== 0)` block). The tank water check uses `tankPosition` (current frame) rather than the proposed new position.

**Wake waves (`Tank.svelte`):** While wading (`getTerrainHeight < 0 && tankPosition.y > -3.5`) and moving above `MIN_WAKE_SPEED`, `wakeTimer` accumulates distance traveled (`+= Math.abs(speed) * delta`). Every `WAX_WAKE_SPACING = 4` world units, two `<Splash>` instances are pushed to a `wakes` `$state` array — one 1.5 units ahead of the tank and one 1.2 units behind, both at world Y = 0 (water surface). Each is removed via its `onremove` callback. Distance-based emission ensures ring spacing is consistent regardless of speed. `wakeTimer` and `wakes` are reset in `reset()`.

**Slope limits** (`Tank.svelte`): `MAX_SLOPE = tan(35°) ≈ 0.70`. Uphill steeper than MAX_SLOPE blocks movement (speed zeroed, position reverted). Overall slope steeper than MAX_SLOPE causes downhill sliding proportional to excess slope. Terrain max slope is ~45° given the vertex height constraint of ±5 per 5-unit cell.

**Differential track steering:** Left and right tracks spin at different rates during turns:
```js
wheelSpinLeft  += (speed - angVel * factor) * delta;
wheelSpinRight += (speed + angVel * factor) * delta;
```

**Track animation speed (`Tank.svelte`):** `spinSpeed` uses `max(speed, accelSpin)` (forward) / `min(speed, accelSpin)` (backward) rather than `speed + accelSpin`. This keeps wheel animation proportional to actual movement when coasting, while still spinning visibly when slope blocks movement (speed=0 but key held). Direction is resolved via `spinDir = speed !== 0 ? sign(speed) : sign(accelSpin)` to handle the standstill case correctly.

**Controls (`Tank.svelte`, `+page.svelte`):**
- `W`/`S` — drive forward/back; `A`/`D` — steer left/right (hull)
- `X` — handbrake: one tap decelerates to a full stop (`BRAKE_DECEL = 6`); cancelled early by pressing `W` or `S`
- `Z` — toggle zoom mode: narrows FOV from 50° → 15° (smooth lerp, `ZOOM_FOV_LERP=8`) and reduces aim sensitivity 4× (`ZOOM_AIM_FACTOR=0.25`) for both mouse and arrow keys
- `M` — toggle mute (handled in `+page.svelte`): calls `THREE.AudioContext.getContext().suspend()/resume()` to globally mute/unmute all Three.js audio; `muted` state shown in locked hint and as a Mute/Unmute button in the help panel
- Arrow left/right — rotate turret; arrow up/down — elevate/depress barrel (clamped to −10°/+40°)
- Mouse (when pointer-locked) — aim turret/barrel; directly updates `turretHeading`/`barrelElevation`

**Mobile / touch controls (`+page.svelte`, `Tank.svelte`, `src/lib/Joystick.svelte`):** Detected at runtime via `'ontouchstart' in window || navigator.maxTouchPoints > 0` in `onMount`; `isTouch` and `touchActive` are `$state` in `+page.svelte`. On touch devices the overlay shows a "Play" button instead of "Mouse Control"; tapping it sets `touchActive = true` and reveals the on-screen controls. Three controls are shown at the bottom of the screen: left joystick (drive/steer), FIRE button (centre), right joystick (aim).
- **`Joystick.svelte`** — self-contained virtual joystick: 110 px outer circle, 44 px knob. Tracks one touch point by ID; clamps knob travel to `OUTER_R - INNER_R = 33 px`; calls `onchange(dx, dy)` with values normalised to `[-1, 1]`. `touchId` is `$state` so `class:active` re-renders when a touch starts/ends.
- **Left joystick** dispatches `tank-touch-drive` custom event; Tank.svelte stores `touchDriveX/Y` and applies them in `useTask` before the input section: deflection > 0.15 sets `upHeld`/`downHeld`/`leftHeld`/`rightHeld`.
- **Right joystick** dispatches `tank-touch-aim`; Tank.svelte stores `touchAimX/Y` and applies rate-based turret/barrel updates after the mouse-aim block: `turretHeading -= touchAimX * TURRET_SPEED * 2 * aimFactor * delta`, barrel uses negated Y (joystick up = elevate).
- **FIRE button** — `touchstart` calls `startCharge()`, `touchend`/`touchcancel` calls `tryFire()`. `touchFireHeld` (plain `let`) mirrors `spaceHeld`/`mouseHeld` so holding fire auto-charges after reload completes.
- **Mute button** — small button at top-right, visible when `touchActive`.
- `touch-action: none` on `.game-container` prevents browser scroll/zoom on the canvas.

**Zoom mode (`Tank.svelte`):** `zoomed` is a `$state(false)` toggled by Z. `currentFov` is a plain `let` (non-reactive) lerped each frame toward `ZOOM_FOV=15` or `NORMAL_FOV=50`; written imperatively to `(cameraRef as THREE.PerspectiveCamera).fov` with `updateProjectionMatrix()` each frame. `aimFactor = zoomed ? ZOOM_AIM_FACTOR : 1` is computed once per frame and applied to all aim inputs (arrow key speed and mouse sensitivity).

**Shell camera tracking in zoom mode (`Tank.svelte`, `Shell.svelte`, `Scene.svelte`):** When zoomed and a shell is in flight (`shellFollow.pos !== null`), the camera look-at target switches from the tank to the shell position. The shell's live `pos` Vector3 is shared into the `'shellFollow'` context at component init — since it's updated in-place each frame, `shellFollow.pos` stays current without per-frame writes. On terrain impact, `handleImpact` overwrites `shellFollow.pos` with a clone of the impact point so the camera holds on the crater during the explosion. When the sequence ends (`removeExplosion` for the tracked shot, or `removeShell` for OOB exits with no explosion), `shellFollow.pos` is nulled and a `'shell-sequence-done'` custom window event is dispatched. Tank listens for this event and auto-exits zoom if `!zoomedAtFireTime` (zoom was OFF when the shot was fired). `trackedShellId` / `trackedExplosionId` plain `let`s in Scene prevent stale events from concurrent/overlapping sequences.

**Firing charge mechanic (`+page.svelte`):** Hold LMB (pointer-locked) or Space to charge. Bar fills over 2 seconds (green → gold) with a centred "VELOCITY" label. Release to fire at current charge level (minimum speed 20 m/s, maximum 50 m/s). At 100% the bar pulses gold for 500 ms then disappears — releasing after that does not fire. Charge state is managed in `+page.svelte` via a `requestAnimationFrame` loop; on fire it dispatches a `tank-fire` custom event with `{ chargeLevel }`. Tank listens for `tank-fire`, computes muzzle world position + velocity vector, and calls `onfire(position, velocity)`. `spaceHeld`/`mouseHeld` are plain `let` (not `$state`) and are only cleared by their own `keyup`/`mouseup` handlers — NOT by `resetCharge()` — to prevent key-repeat from restarting a dismissed charge. The charge bar and reload bar share the same screen position (`top: 1.2rem`, centred) — they are never visible simultaneously.

**Velocity bar fade on fire (`+page.svelte`):** When the player fires, the velocity bar does not disappear immediately. Instead it freezes at the fired charge level and fades out over `FIRE_FADE_DURATION = 1000` ms (`chargeOpacity` animates 1→0, applied via `style="opacity: {chargeOpacity}"`). The gold pulse class is suppressed during the fade (`class:full={chargeLevel >= 1 && fadeStart === null}`). `fadeStart` is a `$state<number | null>` set in `tryFire()`. The RAF tick handles the fade and, when complete, sets `chargeVisible = false`, resets `chargeOpacity = 1`, nulls `fadeStart`, then sets `reloadStart = now` and `reloadProgress = 0` to start the reload. `startCharge` is gated on `fadeStart === null` in addition to `reloadProgress >= 1` so the player cannot start charging during the fade.

**Reload mechanic (`+page.svelte`):** After the velocity bar fade completes, a 2-second reload countdown begins (`RELOAD_TIME = 2000`; total cycle is 3 s including the 1 s fade). `reloadStart` is a `$state<number | null>` set when the fade ends. `reloadProgress` (`$state`, 0–1) is driven by the same RAF loop. The reload bar (dark red → orange) is shown while `reloadStart !== null` (not `reloadProgress < 1`) — this ensures it only appears after the fade, never overlapping the velocity bar. It starts full and drains to empty (`width: (1 - reloadProgress) * 100%`) with a centred "RELOADING" label; disappears when reload completes (`reloadStart` nulled). The Restart button calls `resetCharge()` then resets `reloadStart = null; reloadProgress = 1`. There is no keyboard shortcut for Restart (R was removed to avoid accidental restarts, since Quit also has no shortcut).

**Restart — full remount via `{#key}` (`+page.svelte`, `Scene.svelte`):** `{#key restartKey}<Scene />{/key}` inside `<Canvas>` ensures the entire scene (terrain, trees, tank, shells, explosions) is fully destroyed and recreated on restart. This guarantees proper Threlte/Svelte lifecycle cleanup (all `useTask` callbacks, `onDestroy` handlers, imperative Three.js objects) with no resource accumulation across restarts. The Canvas itself is outside the `{#key}` so the WebGL context is preserved. Scene.svelte calls `initGame()` once at module level — no `restartKey` prop or `$effect` needed.

**Turret and barrel (`Tank.svelte`):** `turretHeading` (relative to hull) and `barrelElevation` are separate `$state` values updated in `useTask`. The template uses nested groups:
```svelte
<T.Group rotation.y={turretHeading}>          <!-- turret ring -->
  <!-- turret mesh, cupola -->
  <T.Group position={[0, 1.29, -0.67]} rotation.x={barrelElevation}>  <!-- pivot at mantlet -->
    <!-- gun mantlet, barrel -->
  </T.Group>
</T.Group>
```
The cupola sits in the turret group (rotates with turret azimuth) but outside the elevation group (does not tilt with barrel).

**Barrel elevation pivot — gun mantlet:** The elevation group pivots at the turret front face (`z ≈ −0.67`), not the turret centre. This keeps the barrel visually anchored to the turret as it elevates. A gun mantlet mesh at the pivot point (`position={[0,0,0]}` in the elevation group) masks the gap. The barrel mesh is offset so its world position is unchanged: `pivot_z + barrel_local_z = turret_centre_z − half_barrel_length`.

**Camera (`Tank.svelte`):** Single chase camera, active only when `chaseCamera` prop is true. Smoothly lerps (factor `CHASE_LERP=3`) to a position behind the barrel — using `absHeading = tankHeading + turretHeading` so rotating the turret swings the camera around the tank. Camera Y is `tankPosition.y + CAMERA_HEIGHT + barrelDownLift`, floored at `terrainHeight(camXZ) + CAMERA_HEIGHT`. `barrelDownLift = max(0, -worldBarrelPitch) * CAMERA_BEHIND * 2` where `worldBarrelPitch = barrelElevation + cos(turretHeading) * tankPitch - sin(turretHeading) * tankRoll` — projects the tank's tilt onto the barrel's azimuth direction. The minus on roll is because positive turretHeading rotates the barrel to the left (−X hull-local), which is downhill when tankRoll > 0 (right side up), so the roll contribution must be negated. Look target is `tankPosition` with Y offset `CAMERA_HEIGHT*0.5 + sin(barrelElevation)*CAMERA_BEHIND*0.4`. `cameraRef` captured via `oncreate`.

**Pointer lock (`+page.svelte`):** `document.documentElement.requestPointerLock()` is called when the player clicks "Use Mouse Control". Mouse aim (`movementX/Y`) accumulates whenever `pointerLockElement !== null`. Escape releases pointer lock (browser-enforced); the overlay reappears automatically via `pointerlockchange`.

**Directional light tracking tank** (`Tank.svelte`): Light is rendered inside `{#if chaseCamera}`. Position and target updated every frame via `lightRef` directly (no reactive overhead). Small shadow frustum (±`SHADOW_HALF` units) for sharp shadows near tank.

**Tank spawn positions (`Scene.svelte`, `Tank.svelte`):** `initGame()` computes spawn positions *before* terrain or tree generation so trees can avoid them. Tanks sit on a circle at `SPAWN_RADIUS = (WORLD_SIZE/2) * 0.8` (300 units), divided into `TANK_COUNT = opponentCount + 1` equal arcs from a random `baseAngle` for per-game variety. Each position gets up to 10% radial jitter (`±SPAWN_RADIUS * 0.1`). Positions are stored in `spawnPositions` (`$state`). The tree grid skips any candidate within `SPAWN_CLEAR = 40` units of any spawn. Scene renders the player tank (index 0, `controlled chaseCamera`) plus opponent tanks via `{#each spawnPositions.slice(1)}`. `onMount` snaps each tank to its spawn via `snapTankToTerrain(spawnX, spawnZ)`.

**Opponent AI (`Tank.svelte`, `Scene.svelte`):** AI runs inside `useTask` when `!controlled`, gated on `!gameOver`. Four states:
- **patrol**: drives toward `aiPatrolAngle` (biased toward terrain centre), scans turret in a ±60° arc. Changes direction every 6–13 s.
- **search**: moves toward `aiLastSeenX/Z` at full speed; within `AI_SEARCH_APPROACH_DIST = 50` units switches to a half-speed creep (`AI_SEARCH_APPROACH_SPEED = 8 m/s` cap — brake when over, drive when under); exits to patrol when within `AI_SEARCH_ARRIVE_DIST = 12` units of the last known position. Turret scans ±60° throughout.
- **engage**: three distance sub-cases share turret tracking and fire logic. Nominal band: approach if target > `AI_MAX_ENGAGE_DIST = 350`; back away if < `AI_MIN_ENGAGE_DIST = 25`; good range in between. After `AI_REPOSITION_MISSES = 3` consecutive misses, `effectiveMaxDist` shrinks (AI closes in if shell fell short) or `effectiveMinDist` grows (AI backs away if overshooting), by 50 / 15 units per excess miss respectively. **Back-away (`tooClose`):** drives away from target but keeps turret tracked and fires as soon as aimed + LOS — no speed or slope gate (no time to be picky at close range). The tooClose block unconditionally tracks the turret toward the target using pure geometry (same formula as cooldown) BEFORE the `if (canHit)` ballistic block runs, so the turret is never left pointing wherever the cooldown happened to leave it even if the ballistic solver fails. If `aiStuckTimer > AI_STUCK_TIMEOUT` (hill blocking the flee path), `fleeH` redirects 90° sideways (`awayH + aiStuckTurnDir * π/2`) rather than pushing into the obstruction; the general stuck-detection block cooperates naturally since it uses the same `aiStuckTurnDir`. **Good range:** seeks flat ground — if `slopeMag = hypot(tankPitch, tankRoll) > AI_MAX_FIRE_SLOPE = 0.15 rad`, drives along terrain contour at `AI_SLOPE_CREEP_SPEED = 3 m/s`; once flat, brakes to stop. Fires only when `!onSlope && speed < AI_STOP_SPEED`. **Both cases** run velocity sampling, two-pass ballistic aim + lead, bias application, and turret/barrel tracking every frame. Fire requires 0.3 s dwell on the aimed condition before `aiFire()`. If LOS lost for > 2.5 s → search.
- **cooldown**: waits 2–3.5 s after firing. Turret heading is tracked unconditionally using pure geometry (`normalizeAngle(atan2(-cdx,-cdz) - tankHeading)`) — no dependency on the ballistic solve — so the barrel always stays on the target even if the solve fails. Barrel elevation is also continuously re-solved and tracked during cooldown so the AI is aimed and ready the moment cooldown ends. On expiry, reads `ownBody.lastShellImpact` (written by Shell.svelte for terrain/tree misses): projects the firer→impact vector onto the firer→target unit vector (`impProj = impDx*tgtNx + impDz*tgtNz`) to compute a signed range fraction (`(tgtDist − impProj) / tgtDist`), scaled to `aiAimBiasSpeed` (clamped ±10 m/s); separately computes the heading difference between firer→impact and firer→target, scaled 0.7× to `aiAimBiasTurret`. These biases are added to the next shot's speed and turret heading. If `lastShellImpact` is null (shell hit a tank), biases and `aiMissCount` are reset to 0. `aiMissCount` increments on each miss and drives the repositioning logic in engage.

**Vision:** 120° FOV cone (±60° from barrel world azimuth) checked via dot product (`dot > 0.5`). LOS: terrain samples along the line from own cupola top to target cupola top (`CUPOLA_H = 1.6` above `tankPosition.y`). Sample count = `max(16, ceil(dist/5))` — one sample per terrain cell (5 u) so no narrow hill peak can slip between two checks at long range; minimum 16 for short ranges. FOV + LOS required for new contact detection (patrol/search). LOS-only (no FOV) for maintaining contact in engage/cooldown. All non-destroyed tank bodies (player and opponents) are candidate targets; nearest visible is chosen.

**Ballistic solver (`aiComputeAim`):** Iterates `v = SHELL_MIN_SPEED` to `SHELL_MAX_SPEED` in steps of 3. For each v computes `disc = v⁴ − g(gd² + 2Δh·v²)`. If `disc ≥ 0`, tests low-angle `tan θ = (v² − √disc) / (g·d)` then high-angle `(v² + √disc) / (g·d)`. Uses the first elevation within `[BARREL_MIN, BARREL_MAX]`. Aims at target mid-cupola (`ty + CUPOLA_H * 0.5`); muzzle height approximated as `tankPosition.y + 1.29`. Stores result in `aiTargetTurretH`, `aiTargetElev`, `aiFireSpeed`. Shot-correction biases (`aiAimBiasSpeed`, `aiAimBiasTurret`) set by cooldown are added at fire time: `aiFireSpeed += aiAimBiasSpeed`, `aiTargetTurretH += aiAimBiasTurret`. `aiFire()` mirrors `fire()` but uses `aiFireSpeed` instead of a charge level.

**AI input flags:** All six input booleans (`upHeld`, `downHeld`, `leftHeld`, `rightHeld`, `turretLeftHeld`, `turretRightHeld`, etc.) are cleared to false each frame for AI tanks. Turret and barrel are driven directly via angle arithmetic (not via the boolean flags), so the Input section's keyboard/mouse aim code is a no-op for AI. `braking` is set imperatively by the engage state. Opponent tanks receive `gameOver` and `onfire={handleOpponentFire}` props; `handleOpponentFire` pushes shells with `tracked: false`.

**AI stuck detection (`Tank.svelte`):** After the state machine, a post-pass checks if `(upHeld || downHeld) && Math.abs(speed) < 0.3`. If this persists for `AI_STUCK_TIMEOUT = 1.5` seconds the AI is considered blocked by terrain too steep for its current heading. It overrides `leftHeld`/`rightHeld` to force a hard turn in `aiStuckTurnDir` direction (+1 = left, −1 = right). If the blockage continues for `3 × AI_STUCK_TIMEOUT` seconds, `aiStuckTurnDir` flips and `aiStuckTimer` resets, so the AI tries the other side. The timer resets to 0 whenever the tank is making progress (`speed ≥ 0.3` or no drive key held). State variables: `aiStuckTimer` (seconds blocked), `aiStuckTurnDir` (±1).

**Exposing component methods:** `export function reset(sx, sz)` in Tank.svelte is called by Scene via `bind:this={tankRef}` → `tankRef.reset(x, z)`. `onMount(() => snapTankToTerrain(spawnX, spawnZ))` handles the initial terrain snap since Tank mounts after Scene's `initGame()` has populated `heights`.

**`const` / `let` temporal dead zone:** In Svelte 5 component scripts, `const` and `let` declarations are NOT hoisted. Any code that runs at initialisation (e.g. `initGame()` called at module level) must appear after all `const`/`let` declarations it depends on.

**Custom hull geometry (`Tank.svelte`):** The hull is a trapezoidal prism built from a `BufferGeometry` (function `makeHullGeometry`). Bottom face extends further forward than the top (front slope ~32° from vertical) and slightly further back (rear ~11° from vertical), making front/back visually distinct. Each face uses its own vertices (non-indexed) so `computeVertexNormals()` gives clean flat shading per face. The geometry encodes absolute tilt-group local coords (`y=0.30` = track top, `y=1.10` = hull top), so the mesh has no position offset. UV coordinates are generated via box projection: each face projects onto its dominant plane (top/bottom → XZ, front/back → XY, sides → ZY), normalised to [0, 1] per face so textures cover each face without stretching.

**Per-frame allocation avoidance:** `_X_AXIS`, `_Y_AXIS`, `_scratchEuler` are declared once as component-level constants and reused inside `useTask` and `fire()` to avoid GC pressure. `cameraPosition` (a `$state` Vector3 read by the template) must still be reassigned to a `new THREE.Vector3` each frame — mutating `.x/.y/.z` in place does not trigger reactivity.

**Shell system (`Scene.svelte` + `Shell.svelte`):** Scene owns a `shells: ShellInstance[]` array (`$state`). Tank's `onfire(position, velocity)` callback pushes a new entry; Scene renders `{#each shells as s}<Shell onremove={() => removeShell(s.id)} .../>`. `removeShell(id)` filters the shell out of the array. On restart, `shells = []` in `initGame()`. Each Shell component:
- Clones `position` and `velocity` on mount; runs its own `useTask` physics loop (gravity, position, quaternion orientation along velocity)
- Updates the group position/quaternion imperatively via `groupRef` (no Svelte reactivity overhead)
- **Out-of-bounds flight:** physics continues past the terrain boundary without sticking. When `!isInBounds(pos.x, pos.z) && pos.y < position.y - 15`, Shell calls `onremove()`. The `!isInBounds` guard is critical — without it, shells fired from high ground would be removed before reaching distant low-lying water. Terrain impact and splash are guarded by `isInBounds` so `getTerrainHeight`'s OOB sentinel of `0` never triggers a false hit.
- **Water splash:** detects crossings of `y=0` in water areas (only when `isInBounds`) by comparing `prevY` to `pos.y` each frame. Each crossing (upward or downward) mounts a `<Splash>` component. Multiple splashes run concurrently via a `$state<{id,x,z}[]>` array.
- **Terrain impact:** (only when `isInBounds`) when `pos.y <= getTerrainHeight(pos.x, pos.z)`, sets `done = true` and hides the mesh. The `useTask` keeps running until all active splashes finish, then calls `onremove()`.
- Shell material: `MeshStandardMaterial` copper/brass (`#c87830`), metalness 0.8, roughness 0.3, emissive `#7a3a08` at 0.4 intensity for visibility in shadow.

**Splash component (`Splash.svelte`):** Props: `x`, `z`, `onremove`. Manages 3 rings with staggered delays (0, 0.4, 0.8 s); each expands from radius 0 to 6 over 2 s while fading from opacity 0.7 to 0. Each ring has its own `RingGeometry(0.001, 0.3, 64)` and `MeshBasicMaterial`; the geometry's position buffer is updated in-place each frame via `updateRingRadius` (inner/outer ring vertex rows rewritten directly), keeping the ring width constant at 0.3 regardless of expansion radius. All 3 meshes are always mounted (no `{#if}`) with `visible={false}`, shown/hidden via refs. `RingGeometry` vertex layout with default `phiSegments=1`: vertices 0–64 = inner ring, vertices 65–129 = outer ring. Ring meshes sit at `y=0` (water surface). Ring material uses `color="#ffffff" depthWrite={false}` — white so blending with the water gives a natural cyan tint; `depthWrite={false}` prevents rings from writing to the depth buffer (which would create holes in any transparent geometry that renders after them). `depthTest` is the default `true` so terrain properly occludes rings — do **not** set `depthTest: false`, which would make rings visible through terrain. `polygonOffset: true, polygonOffsetFactor: -1, polygonOffsetUnits: -1` nudges each ring's NDC depth slightly toward the camera, breaking the z-fighting tie with the coplanar water plane — this works from both above and below the surface because polygon offset operates in NDC space (camera-direction-independent), unlike a y-position shift which would make rings invisible from underwater. `renderOrder={1}` keeps rings in the transparent pass after the water plane writes its depth values. All geometries and materials are disposed in `onDestroy`. Calls `onremove()` once all rings have completed. Used by `Shell.svelte`, `Explosion.svelte`, and `Tank.svelte` (wake waves).

**Tree system (`Tree.svelte`, `Scene.svelte`):** `Scene.svelte` generates a `TreeSpec[]` array (`$state`) during `initGame()`. Candidate positions are sampled on a 35-unit jittered grid; only spots in the grass biome (height 5–23), with slope ≤ 0.5, and outside a 40-unit spawn radius are kept. Each spec carries: `x/y/z` (world position, `y` = terrain height), `scale` (0.6–1.5), `rotation` (random Y), `numLayers` (2–4 conifer tiers), `colorIndex` (0–4, picks from five dark-green hues), `burntAt` (null or a `Date.now()` timestamp set when the tree is ignited). `nextTreeId` is a persistent counter (not reset on restart) so Svelte always treats each new tree as a fresh component. Trees are excluded within `SPAWN_CLEAR = 40` units of any spawn position (checked against `newSpawns` before the array is assigned to `$state`). `Tree.svelte` creates geometries at component init (not in `$effect`): one `CylinderGeometry` trunk + `numLayers` stacked `ConeGeometry` tiers, each shrinking by factor `1 - i*0.22` and overlapping 52% with the tier below. Two `MeshStandardMaterial` instances (trunk brown `0x5c3d1e`, foliage from palette). All disposed in `onDestroy`. Trees near explosion craters may visually float if the terrain is deformed under them.

**Tree fire system (`Tree.svelte`, `Scene.svelte`):** When a shell impacts (`handleImpact`), any tree within `IGNITION_RADIUS = 10` units has its `TreeSpec.burntAt` set to `Date.now()` via the `$state` deep-reactive proxy — Svelte propagates this to the `burntAt` prop in `Tree.svelte`. Fire is handled by a `<Flames>` component always mounted in the tree template (so shader warmup fires at game start). `Tree.svelte` sets `isBurning = $state(false)` → Flames prop is reactive. `useTask` tracks `Date.now() - burntAt` each frame; sets `isBurning = true` on first tick, lerps foliage/trunk colours toward charcoal, sets `isBurning = false` and `isBurnt = true` (plain `let`) when `BURN_DURATION = 60_000` ms elapses. The `<Flames>` component receives `scale={Math.max(1, scale) * scale}` (larger trees burn more dramatically, outer flames stay within the foliage radius) and `burnDuration={BURN_DURATION / 1000}` (cubic falloff matching the colour animation). Charred colours: foliage → `0x1c1206`, trunk → `0x0e0905`.

**Tree trunk collision (`Scene.svelte`, `Tank.svelte`):** `Scene.svelte` maintains a `treeTrunks: {x, z, r}[]` array (stable reference, non-reactive) and exposes it via `setContext('treeTrunks', treeTrunks)`. It is populated / replaced in `initGame()` using `treeTrunks.length = 0; for (const t of newTrees) push(...)` so the same object reference is always valid in child components. Trunk radius `r = 0.18 * t.scale` (matches the `CylinderGeometry` base radius in `Tree.svelte`). Tank.svelte reads this once via `getContext` and iterates it every physics frame. Collision check: for each trunk compute `distSq`; if `distSq < (TANK_RADIUS + trunk.r)²`, push `newX/newZ` out to the contact boundary. Speed is zeroed only when the velocity component along the trunk→tank normal is negative (i.e., moving into the trunk) — this allows the tank to slide along the trunk surface rather than hard-stopping when approaching at an angle. `TANK_RADIUS = 1.4` (slightly larger than `TRACK_W = 1.1`).

**Tree shell hit detection (`Scene.svelte`, `Shell.svelte`):** `Scene.svelte` maintains a `treeVolumes: {x, z, y, top, canopyR}[]` array (stable reference) alongside `treeTrunks` and exposes it via `setContext('treeVolumes', treeVolumes)`. Populated in `initGame()` using `treeApexHeight(scale, numLayers)` — a mirror of Tree.svelte's layer-stacking geometry (trunkH·0.6 start, each tier `baseH·(1−i·0.22)`, advancing `h·0.52` per layer). `canopyR = 1.8 · scale` (widest foliage tier). Shell checks each volume every physics frame: if `dx²+dz² < canopyR²` AND `pos.y > vol.y AND pos.y < vol.top`, Shell calls `onimpact(pos)` (triggers an explosion in the canopy + ignites the tree and any within `IGNITION_RADIUS = 10` units via `handleImpact`) and sets `done = true`.

**Tank-tank collision (`Scene.svelte`, `Tank.svelte`):** `Scene.svelte` provides a `tankBodies: {x, z, pushVx, pushVz, hitAt}[]` array via context. Each `Tank` owns one entry: initialised to spawn position, updated to resolved position every frame, removed in `onDestroy`. Each frame, before slope/obstacle checks, the tank applies `ownBody.pushVx/pushVz * delta` to `newX/newZ` (external impulse from collisions) then decays it with `Math.pow(PUSH_DECAY=0.1, delta)`. The collision pass (after tree-trunk) resolves overlap by pushing `newX/newZ` out to the `TANK_RADIUS*2` contact boundary, then — if A's speed has a component toward B (`vDotN < 0`) — applies the equal-mass collision formula: impulse = `(1+RESTITUTION)/2 * |vDotN|`; B's `pushVx/pushVz` receives the impulse in the −n direction; A's scalar speed is reduced by the projected component. Bodies with `hitAt !== null` (destroyed) are skipped in collision resolution.

**Tank destruction (`Shell.svelte`, `Tank.svelte`, `Scene.svelte`):** Shell checks XZ distance (`HIT_RADIUS = 2.5`) AND vertical distance (`HIT_HEIGHT = 3.0`, `Math.abs(pos.y - body.y) < HIT_HEIGHT`) to every tank body each physics frame — the height check prevents shells that fly over any tank from registering a hit. On a hit the firer-grace check runs: skip if `firerGraceTimer > 0` (first 0.3 s). After the grace window the firer is hittable — supporting lofted/arcing self-hits. The firer is identified by numeric `body.uid === excludeBodyUid` (a plain number); using an object reference would fail silently because Svelte 5 `$state` deep-proxies the `shells` array contents, breaking `===` identity. `body.uid` is a random 32-bit integer assigned at tank init; `body.y` is updated every physics frame alongside `x/z`. On hit: Shell writes `body.lastHit = { dist, wx, wz }` (not `hitAt`) and sets `done = true` — no terrain explosion. Tank reads `ownBody.lastHit` the next frame, computes damage from hit distance (`CENTER_HIT_DAMAGE = 50`, `EDGE_HIT_DAMAGE = 15`, interpolated by `1 - dist/HIT_RADIUS`), and starts burning (`burning = true`). While burning, physics is frozen, fire plays at the hit offset (`hitOffsetX/Z` clamped to ±1.5 units from tank centre), and health drains at `burnDamageRate = totalDamage / burnDuration` per second. If health reaches 0: Tank sets `ownBody.hitAt = Date.now()`, calls `onexplode(tankPosition)` (terrain deformation + `Explosion` component in Scene), hides the tank group, sets `tankDestroyed = true`. If health > 0 when `burnElapsed >= burnDuration`, fire stops and the tank resumes normal physics. Destroyed bodies have `hitAt !== null` — other systems skip them in collision resolution and hit detection.

**Tank fire effect (`Flames.svelte`, used by `Tank.svelte` and `Tree.svelte`):** Shared imperative fire component. Tank passes `baseHeight={0.3}` (hull level), no `scale` override (defaults 1.0), no `burnDuration` override (defaults 0 = no fade). `burning` toggles visibility; elapsed resets to 0 when it goes false. Multi-frequency sine flicker on `scale.y`, `scale.x/z`, opacity, and PointLight intensity. Uses `MeshStandardMaterial` with emissive so flames glow even in dark areas. Tank declares `burning = $state(false)` and `hitOffsetX/Z = $state(0)` so prop updates are reactive. Flame position XZ offset: `hitOffsetX/Z = clamp(hitWorldX/Z - tankX/Z, -1.5, 1.5)`.

**Health HUD (`+page.svelte`):** Tank health is HTML, not in-world. See architecture entry above. Health constants in `Tank.svelte`: `TANK_MAX_HEALTH = 100`, `CENTER_HIT_DAMAGE = 50` (2 centre hits = death), `EDGE_HIT_DAMAGE = 15`, `CENTER_BURN_DURATION = 3 s`, `EDGE_BURN_DURATION = 0.7 s`.

**Game-over state (`+page.svelte`, `Scene.svelte`, `Tank.svelte`):** `gameOver` is a `$derived` in `+page.svelte`: true when (a) player tank is destroyed, OR (b) only 1 non-destroyed tank remains. `playerWon = gameOver && !player.destroyed`. On game over: pointer lock is released via `document.exitPointerLock()` in a `$effect`; charge/reload bars are hidden; the overlay shrinks to Restart + Quit buttons only; big centered text ("You Won" green / "Game Over" red) appears at `z-index: 30`. `gameOver` is passed as a prop through `Scene` → player `Tank`. In `Tank.svelte`, a game-over camera block runs at the top of `useTask` (before `if (tankDestroyed) return`) — it animates the camera from its current chase position to `(0, 800, 0)`. Position lifts over the full 30 s (quadratic ease-out). Orientation rotates to top-down in 5 s (separate `tRot = elapsed/5` quadratic ease-out) via quaternion SLERP — `_scratchQuat.slerpQuaternions(gameOverCamStartQuat, _GAME_OVER_END_QUAT, easedRot)` — so the player sees their tank from above quickly. `_GAME_OVER_END_QUAT` is a component-level constant (dummy PerspectiveCamera with `up=(1,0,0)` looking down at origin). No `lookAt` is used during game over — eliminates gimbal-lock snap. The normal chase camera block is gated on `!gameOver`. Player keyboard controls (WASD) still work during game over if the player tank is alive; the camera just no longer follows. `GAME_OVER_LIFT_DURATION = 30`, `OVERVIEW_HEIGHT = 800` — vertical visible span ≈ 746 units (FOV 50°), covering the terrain without showing the water margin on the shorter vertical screen dimension.

**Visual damage (`Tank.svelte`):** Two effects accumulate as health drops, both driven by `damageFraction = 1 − health/100`. Updates are throttled to when `damageFraction` changes by >0.005.
- **Per-face hull dents:** Each of the 6 hull quad-faces is displaced inward or outward along its face normal by a seeded-random amount (seeded by `ownBody.uid` so the pattern is unique and stable per tank). All 6 vertices of each quad move together, so face normals don't change and `computeVertexNormals()` is not needed for dents alone. Dents start at 85% health and reach max 0.075 units per face displacement at 0 HP.
- **Panel removal:** The hull position buffer has a known layout (quad 0 top [0..17], quad 1 bottom [18..35], quad 2 front [36..53], quad 3 back [54..71], quad 4 left [72..89], quad 5 right [90..107]). Back plate bottom vertices (Y indices 58/61/67, Z indices 59/62/68) sweep from BY=0.3→TY=1.1 and BZB=1.35→TZB=1.2 as damage goes 25%→75% (health 75%→25%). Front plate bottom vertices (Y indices 43/49/52, Z indices 44/50/53) do the same sweep as damage goes 45%→95% (health 55%→5%). At t=0.99 the face is nearly degenerate (invisible). `computeVertexNormals()` is called after panel changes. `hullMaterial` uses `DoubleSide` so the inner face of peeling panels is visible.
- `reset()` restores `origPos` into the position buffer and calls `computeVertexNormals()`.

**Explosion system (`Explosion.svelte`):** Created by Scene when a shell impacts terrain (`onimpact` → `handleImpact` → `explosions.push`). Components:
- **Fireball:** `SphereGeometry` scaled via `sin` curve over 0.6 s then hidden; opacity fades 1→0.
- **Rocks:** 10 `IcosahedronGeometry` meshes with randomised size, azimuth, elevation (0.08–1.81 rad), and speed (4–20 m/s). Ballistic physics + angular spin per frame, updated imperatively via `rock.mesh`. Land when `pos.y <= getTerrainHeight` (only when `isInBounds`); hidden on landing. Each landed rock calls `onrockland` to raise terrain slightly (distributing crater depth across all rocks). **Grace period:** landing is not checked for the first 0.15 s — this prevents rocks from immediately registering as landed on sloped terrain at the impact point.
- **Rock water splashes:** each rock tracks `prevY`; detects crossings of `y=0` in water areas (same `isInBounds` + terrain-height-<0 guard as Shell) and mounts a `<Splash>`.
- **Water drag (split by axis and debris type):** while submerged (`pos.y <= 0` in a water area), horizontal velocity, vertical velocity, and angular velocity are decayed separately each frame via `Math.pow(DRAG, delta)`. Rocks: `ROCK_DRAG_HORIZ=0.25`, `ROCK_DRAG_VERT=0.50`, `ROCK_DRAG_SPIN=0.20`. Flat tank panels: `PANEL_DRAG_HORIZ=0.06`, `PANEL_DRAG_VERT=0.30`, `PANEL_DRAG_SPIN=0.06` — panels catch far more water resistance. Initial ejection speed is unchanged; the drag acts only once submerged.
- **Removal:** `useTask` calls `stop()` + `onremove()` only when fireball done AND all rocks landed AND all splashes finished.

**Muzzle world position (`Tank.svelte` `fire()`):** Barrel tip at `z=−2.25` in elevation-group local space. Transform chain: `Rx(barrelElevation)` → add pivot offset `(0, 1.29, −0.67)` → `Ry(turretHeading)` → `Euler(tankPitch, 0, tankRoll)` → `Ry(tankHeading)` → add `tankPosition`. Same chain (without the pivot offset step) gives the firing direction unit vector.

**Terrain textures (`Scene.svelte`):** `MeshStandardMaterial` with `onBeforeCompile` for three-way biome blending. Grass textures (`Grass006`) occupy the material's primary `map`/`normalMap`/`roughnessMap` slots; sand (`Ground079L`) and snow (`Snow010A`) are passed as custom uniforms. A `vHeight` varying carries world Y from the vertex shader. Two blend weights are computed per fragment: `grassBlend = smoothstep(3, 5, h)` (sand→grass) and `snowBlend = smoothstep(24, 27, h)` (grass→snow) — each applied to colour, roughness, and normal maps in sequence. Vertex colours are white (1,1,1) on all land so textures show naturally; underwater vertices use a blue tint `(0.35, 0.55, 0.9)`. All textures tile at `repeat(60, 60)` (~12 world units per tile). Texture files live in `static/textures/`; only `_Color.jpg` (sRGB), `_NormalGL.jpg`, and `_Roughness.jpg` variants are used.

**Tank textures (`Tank.svelte`):** A shared `loadTex(prefix, suffix, srgb)` helper loads any PBR texture set from `static/textures/`. All four PBR maps are used: `Color` (sRGB), `NormalGL`, `Roughness`, `Metalness`; both `metalness` and `roughness` scale factors are set to 1.0 so the maps drive the values fully.
- **Hull + turret** (`hullMaterial`, shared as `turretMaterial`): texture set `Metal047B`. Tinted via the `tankColor` prop (hex string). Each colour is normalised so its brightest channel = 255, which tints without darkening the texture. Scene defines `TANK_COLORS = ['#CBFF70', '#FFD060', '#80CCFF', '#FF8055', '#CC80FF', '#60FFD0']` (olive, sand, steel blue, rust, purple, mint) — index 0 = player, 1–5 = opponents.
- **Barrel** (`barrelMaterial`): texture set `Metal055A`, no colour tint (natural metal colour).
- The custom hull `BufferGeometry` has no auto-generated UVs, so `makeHullGeometry` builds them explicitly via box projection (see above).

**Three.js memory management:** Every `BufferGeometry`, `Material`, and `Texture` created imperatively must be disposed when the component is done with it — Three.js/WebGL does not free GPU memory automatically. Rules:
- Always pair `new THREE.XxxGeometry()` / `new THREE.XxxMaterial()` / `textureLoader.load()` with `onDestroy(() => { geo.dispose(); mat.dispose(); tex.dispose(); })`.
- Access material maps for disposal via `mat.map?.dispose()`, `mat.normalMap?.dispose()`, etc.
- For objects that are replaced (e.g. `terrainGeo` reassigned in `initGame()`), capture `const prev = terrainGeo` before reassigning and call `prev.dispose()` after the new object is ready.
- **Critical anti-pattern — reactive geometry args:** `<T.RingGeometry args={[reactiveValue, ...]} />` creates a new GPU buffer every render frame when the reactive value changes. Instead, create the geometry once and animate via `mesh.scale`, or update `BufferAttribute` data directly. The `args` prop should only receive constants.
- Threlte's declarative `<T.XxxGeometry args={[constants]} />` (with non-reactive args) is fine — Threlte disposes those when the component unmounts.

**Water rendering (`Scene.svelte`):** The water surface is a `MeshBasicMaterial` (not `MeshStandardMaterial`) plane at y = 0, colour `#1a6fa8`, opacity 0.6, `DoubleSide`. `MeshBasicMaterial` is unlit, so its rendered colour exactly matches the hex value — essential for it to match the scene background when the camera is underwater. The plane is `WATER_SIZE = WORLD_SIZE + 40` (20 units wider than terrain on each side).

**Water skirts (`Scene.svelte`):** Four vertical panels hang from y = 0 down to y = −500 at each side of the water perimeter (at ±`WATER_SIZE/2`). They use the same `MeshBasicMaterial` colour and **same opacity (0.6)** as the water surface — critical: if the skirts were opaque and the surface transparent, the two would blend differently with the background and produce a visible seam. With matching transparency, the blend `60% × #1a6fa8 + 40% × background` is identical whether the camera's line of sight hits the surface or a skirt.

**Sky background (`Scene.svelte`):** `scene.background` is set once to sky colour `#87CEEB` via `useThrelte().scene`. No per-frame switching — the matching opacity between the water surface and skirts makes the underwater view look consistent without needing to change the background colour.

**Seeded RNG (`src/lib/rand.ts`, `Scene.svelte`):** `mulberry32(seed: number): () => number` — Mulberry32 PRNG; deterministic given the same seed, enabling identical terrain/spawns/trees across clients in multiplayer. `Scene.svelte` generates `const gameSeed = (Math.random() * 2 ** 32) | 0` once, creates `const rand = mulberry32(gameSeed)`, and all internal `Math.random()` calls in terrain height generation, spawn positions, and tree placement are replaced with `rand()`. The `generateHeights()` function closes over `rand` (no parameter). In single-player the seed is generated locally; in multiplayer the host's seed is broadcast in the `game_start` message so all clients reproduce the identical world.

**Multiplayer infrastructure:** The relay server runs in-process alongside the SvelteKit HTTP server on the same port, using a WebSocket server in `noServer: true` mode that intercepts HTTP upgrade events on the `/ws` path.

- **`src/lib/rand.ts`** — exports `mulberry32` seeded PRNG (see above).
- **`src/lib/mp.svelte.ts`** — module-level WebSocket singleton (`mp` state object + `connect`, `send`, `leaveRoom`, `disconnect` functions). Persists across client-side navigation so the connection survives the lobby→room route transition. Also exports `TANK_COLORS` array. `connect(name)` is idempotent — calling it while already connected just re-sends `set_name`. The `mp` object holds: `connected`, `clientId`, `rooms` (lobby list), `room` (current `RoomState`), `pendingRoomId`, `joinError`, `pendingJoiners` (incoming requests), `kicked`, `gameStart`, `latestPlayerLeft` (set when relay sends `player_left`; game page processes and nulls it).
- **`src/lib/types.ts`** — extended with multiplayer protocol types alongside existing game interfaces. Key additions:
  - Interfaces (plain object shapes): `RoomPlayer`, `RoomSummary`, `RoomState`, `TankSnapshot`
  - Discriminated union message types (must be `type`, not `interface`): `BenchmarkMsg` (`{ type: 'benchmark'; score: number }` — sent once on page load, `score` = ops/ms from a trig-heavy benchmark loop), `SetNameMsg`, `PlayerInputMsg` (seq + movement booleans + `fire: number | null`), `GameStateMsg`, `ShellFiredMsg`, `ShellRemovedMsg`, `ExplosionMsg`, `TreeIgnitedMsg`, `GameOverMsg`, `PlayerLeftMsg` (`{ type: 'player_left'; clientId: string; name: string }`), `ForwardedInputMsg` (extends `PlayerInputMsg` with `clientId`)
  - `ClientMessage` and `ServerMessage` union types
  - Helpers: `parseMessage(raw: string)` and `encodeMessage(msg)`
- **`src/lib/relay.ts`** — in-memory relay server; exported as `createRelay(wss: WebSocketServer): void`. Internal state: `clients: Map<string, RelayClient>`, `rooms: Map<string, RelayRoom>`. Room codes are 6 chars from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no 0/O/1/I ambiguous chars). Key behaviours: `electHost()` picks the client with the highest `benchmarkScore` as physics host; `broadcastRoom()` iterates only `room.playerIds` (room-isolated, no cross-room leaks); server-side 30 s countdown `setTimeout` terminates on unanimous cancel, too-few-players, or elapsed; `launchGame()` assigns host tankIndex 0, generates seed, broadcasts `game_start`; `forwardToHost()` appends `clientId` to `player_input` messages; `forwardToGuests()` (host only) dissolves room on `game_over`. When a non-host player disconnects mid-game, `removeFromRoom` broadcasts `{ type: 'player_left', clientId, name }` to remaining players rather than ending the game — the clients handle game-over detection locally.
- **`tsconfig.relay.json`** — separate TypeScript compilation for relay: `rootDir: src/lib`, `outDir: build`, includes `relay.ts` + `types.ts`. Produces `build/relay.js` and `build/types.js`. Required because adapter-node only bundles files imported by SvelteKit routes, so relay.ts (imported by no route) needs its own compile step. `import type` declarations in relay.ts (Three.js, ws types) are stripped — no unwanted runtime deps in output.
- **`server.js`** — production entry point: imports `build/handler.js` (SvelteKit) and `build/relay.js`, creates a shared `http.createServer(handler)`, attaches a `WebSocketServer({ noServer: true })`, intercepts `upgrade` events on `/ws`, listens on `process.env.PORT ?? 3000`. This is the cPanel Node.js app startup file.
- **`vite.config.ts` relay plugin** — `relayPlugin()` creates a WS server in `noServer: true` mode, calls `createRelay(wss)`, and intercepts Vite's `httpServer` upgrade events on `/ws`. All other upgrade paths (Vite HMR) are passed through. This makes `npm run dev` work single-port without a second server.
- **`package.json` build script**: `"build": "vite build && tsc --project tsconfig.relay.json"` — tsc step runs after vite to produce `build/relay.js`.
- **Adapter**: `@sveltejs/adapter-node` (replaces `adapter-auto`). Produces `build/handler.js` consumed by `server.js`.

**HTML overlays over Canvas:** Wrap `<Canvas>` in a `position: relative` div; overlay divs use `position: absolute; z-index: 10`. The game overlay uses `pointer-events: none` on the container and `pointer-events: auto` on the panel so the canvas remains interactive behind it. The charge bar uses `z-index: 20` and is always rendered when `chargeVisible`, independently of the lock state overlay.

**Mute system:** `muted` state lives in `+page.svelte` (game). Toggled by M key or the Mute/Unmute button in the help panel. Passed as a prop to `Scene.svelte`, which calls `getAudioListener()?.setMasterVolume(muted ? 0 : 1)` in a `$effect` — this controls the `THREE.AudioListener` master gain node, which all positional audio passes through. `AudioContext.suspend()` is deliberately NOT used because Threlte's `play()` calls `context.resume()` internally on every sound, immediately overriding a suspend. The single-player setup page (`src/routes/single/+page.svelte`) has a "Mute Sounds" checkbox; if checked, `&muted=1` is appended to the game URL and the game page initialises `muted = $state(true)` from the query param.

**Audio system (`Scene.svelte`, `Tank.svelte`, `Shell.svelte`, `Tree.svelte`):** Positional stereo audio via `@threlte/extras` declarative components (`AudioListener`, `PositionalAudio`). `PositionalAudio` handles buffer loading, AudioContext resume on play, and cleanup on `onDestroy` automatically. No manual `THREE.AudioLoader` or context setup needed. Audio files are `.mp3` only (`static/audio/`).
- **Setup:** No audio code in `Scene.svelte`. `@threlte/extras` uses a module-level Map (`useThrelteAudio`) so all `<PositionalAudio>` components in the scene find the single `<AudioListener>` automatically by id (default `"default"`).
- **AudioListener (`Tank.svelte`):** `<AudioListener />` mounted as a child of `<T.PerspectiveCamera>` inside the `{#if chaseCamera}` block (player tank only). Being a child of the camera means listener position/orientation tracks the camera — essential for correct stereo panning. Must mount before any `<PositionalAudio>` in the scene (guaranteed since the player tank renders before opponents in Scene.svelte).
- **Engine sound (`Tank.svelte`):** `<PositionalAudio src="/audio/diesel-engine.mp3" loop autoplay volume={0.6} refDistance={30} playbackRate={enginePlaybackRate} />` inside the outer tank `T.Group`, inside `{#if !tankDestroyed}`. `enginePlaybackRate` is `$state(0.5)` updated every frame in `useTask` (`0.5 + Math.abs(speed) * 0.04`). Unmounting via `{#if}` stops the sound automatically when the tank is destroyed.
- **Shot sound (`Tank.svelte`):** `<PositionalAudio src="/audio/shot.mp3" bind:this={shotRef} refDistance={40} maxDistance={600} />` inside the same `{#if !tankDestroyed}` block. `shotRef` is `$state()`. Called via `shotRef?.play()` in `fire()` and `aiFire()`. If called before buffer loads, `play()` queues playback until the buffer is ready.
- **Shell whistle (`Shell.svelte`):** `<PositionalAudio src="/audio/shell-fly.mp3" loop autoplay bind:this={whistleRef} refDistance={20} maxDistance={400} volume={0.5} />` inside the shell's `T.Group`. Stopped via `whistleRef?.stop()` in the `done` block of `useTask`.
- **Tree fire (`Tree.svelte`):** `<PositionalAudio src="/audio/tree-on-fire.mp3" loop autoplay volume={fireSoundVolume} refDistance={25} maxDistance={300} />` inside the tree's `T.Group`, wrapped in `{#if burntAt !== null && !isBurnt}`. Mounts with `autoplay` when ignition starts; `isBurnt` is `$state(false)` so unmounting (and auto-stop) triggers when burn completes. `fireSoundVolume` (`$state(1.0)`) fades `1→0` over the burn duration via `useTask`.
- **Explosion sound (`Explosion.svelte`):** `<PositionalAudio src="/audio/explosion.mp3" autoplay volume={tankExplosion ? 1.5 : 1.0} refDistance={50} maxDistance={800} />` as a child of the fireball `T.Mesh` (inherits the explosion world position). `autoplay` fires immediately on buffer load.
- **Audio files:** `static/audio/` holds `.mp3` for: `diesel-engine`, `shot`, `shell-fly`, `tree-on-fire`, `explosion`.

**iOS audio unlock (`src/lib/audioUnlock.ts`, `src/routes/single/+page.svelte`, `src/lib/Tank.svelte`):** iOS suspends any `AudioContext` created before a user gesture; sources started against a suspended context silently fail and won't recover on `resume()`. Fix: create a fresh `AudioContext` inside the user gesture (iOS starts it in `running` state). `audioUnlock.ts` exports `unlockedCtx: AudioContext | null` and `unlockAudio()`. The single-player setup page calls `unlockAudio()` inside the `startGame` onclick (which calls `goto()` for SvelteKit navigation, keeping the gesture alive). `unlockedCtx` is a module-level variable that persists across client-side navigation. When the game page's Play/touch button fires the `tank-unlock-audio` custom event, Tank.svelte's handler calls `THREE.AudioContext.setContext(unlockedCtx ?? new AudioContext())`, then the scene remounts (via `restartKey++`) so all `<PositionalAudio>` components initialise against the live context.

**Mobile touch controls (`src/routes/game/+page.svelte`, `src/lib/Joystick.svelte`, `src/lib/Tank.svelte`):** Touch UI appears only on touch devices (`isTouch = $state`, detected via `'ontouchstart' in window || navigator.maxTouchPoints > 0`). Two virtual joystick instances dispatch `tank-touch-drive` and `tank-touch-aim` custom window events with `{dx, dy}` in `[-1, 1]`. A FIRE button triggers the charge/fire mechanic via `touchFireHeld`. A Zoom button dispatches `tank-touch-zoom`. Mute and Quit buttons sit in a separate `touch-hud` strip at top-right. Layout adapts via CSS `@media (orientation: portrait)`: left group stacks `column-reverse` (stick below, Zoom+FIRE above). CSS on the container: `touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none` suppresses iOS text-selection on long-press.
- **`Joystick.svelte`:** Tracks a single touch by `identifier`. `onEnd` resets knob and calls `onchange(0, 0)`. `touchId` must be `$state` (used in `class:active`).
- **Proportional drive in `Tank.svelte`:** `touchDriveWasActive` pattern — set true while joystick active, cleared on release. When active, applies `speed += -touchDriveY * ACCEL * delta` and `tankHeading += -touchDriveX * TURN_SPEED * delta` proportionally. All keyboard flags (`upHeld` etc.) are cleared while touch drive is active so the two systems don't conflict.
- **Touch aim in `Tank.svelte`:** `turretHeading -= touchAimX * TURRET_SPEED * 2 * aimFactor * delta`, barrel likewise. Applied after mouse aim so both can coexist.
- **Dev server network access (`vite.config.ts`):** `server: { host: true }` binds to all interfaces so devices on the LAN can reach the dev server by IP address. Machine-name access (`hp_omen`) requires `allowedHosts: ['hp_omen']` — IP is sufficient for testing on mobile.
